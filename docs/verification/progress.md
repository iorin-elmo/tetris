# 検証記録

設計書の Phase 1 → 6 の順に、共有エンジンから実装する。原作実機・Raspberry Pi 実機での確認結果は、実測するまで合格扱いにしない。

## PROJECT_DEFAULT

60Hz、DAS 150ms、ARR 30ms、接地30tick、接地リセット15回、出現0tick、消去6tick、ガベージ移動30tick、上昇上限8行。Miniの火力とB2B例外、PCのREN/B2B非加算、TETR.IO風ガベージは未実測の初期ルール。SRSは90度のみ。

## Phase 1

Vitest 33件成功。シード再現、7-bag、全7種×左右×4遷移、壁/床キック、HOLD、PC・火力・相殺を確認。TypeScript検査・Vite本番ビルド成功。Chromiumで実際のキーボード入力・HOLD・一時停止・ホーム復帰を確認。GitHub公開リポジトリへpush済み。

## Phase 2

マラソン/40 LINES、150/40ライン達成条件、スコア/時間/自己ベスト保存、キーボードとゲームパッド別割当、DAS/ARR、デッドゾーン、配色・模様・音量・ゴーストを実装。E2Eで3連続終了→再試行と設定永続化を検証する。実物ゲームパッドの操作感は未検証。

結果: Chromium E2E 3件成功（うち1件で3連続終了/再試行）。型検査成功。

## Phase 3

合法な回転・左右移動経路を列挙し、穴/高さ/凸凹/消去数で評価するCPUを実装。EASY/NORMALは1手、HARDは上位3候補の2手読み。各探索は180ノードに制限し決定論的。CPU1〜9体とローカルFFA。対戦火力・ガベージ2方式・全ターゲット方式の共通関数を追加。Vitest 39件成功。実機の原作挙動との照合は未実施。

## Phase 4

WebSocket部屋作成・コード/URL招待、ホスト権限/移譲/キック、3秒カウントダウン、状態権威サーバー+ローカル予測・未確認入力の再実行、10Hzスナップショット、再同期、30秒の復帰猶予を実装。

統合テストで権限拒否、攻撃値の偽装拒否、重複seq拒否、Origin拒否、途中参加観戦、秘密トークン復帰・ローテーション・猶予超過移譲を確認。Chromiumの独立した2コンテキストで招待→対戦→再読込による復帰→結果→ロビー→再戦成功。

PC上の同一ホストでの検証であり、ラズパイ・実インターネット経由WSSの検証ではない。

## Phase 5

10人FFA、11人目拒否、NEXT 5固定、6対4、7人チーム拒否、空チーム許容、非空1チームでの開始拒否、味方ターゲット拒否をWS統合テストで確認。進行中のルールを凍結したまま次試合の設定を変更できることも確認。

スキルのロバスト正規化・低信頼度縮約、人数差を許容する幅512のビーム探索、3候補プレビューと明示適用を実装。候補・権限・人数・再現性を検証。

Chromiumで自分1盤面+他9盤面を表示し、自盤面幅が小盤面の2倍以上であること、390px幅で横にはみ出さないことを確認。ゲームパッドAPIの模擬入力でHOLD・メニュー開閉・切断時の保持解除を確認。実物パッドの遅延/操作感は未検証。

## Phase 6

systemd、Caddy、nginx代替、MyDNS HTTPS更新/30分タイマー、SQLite WAL、バックアップ、受理入力/シードのリプレイ検証、CI/Pagesを用意。

- 型検査・本番ビルド成功。Vitest 53件成功（切断中に試合が終了してから復帰するケースも確認）。
- Chromiumの全E2E 10件成功。MyDNS更新は実通信を模擬したPythonテスト2件成功（実アカウントへの更新は行わない）。
- Chromiumの通常対戦に加え、RTT 30/100/200ms・±5msの揺らぎ・一部snapshot欠落で対戦を維持し、双方の結果表示を確認。
- Chrome・Firefox・Edgeで各4件（操作/HOLD/ポーズ、3連続終了→再試行、設定保存、CPU対戦）の計12件成功。
- 稼働中SQLiteのオンラインバックアップ成功。別のコピーを開きintegrity_check=ok、保存済み7試合の読取を確認。元DBもintegrity_check=ok。
- 決定論的リプレイの完全状態/統計の単体テスト成功。実際のE2Eで保存した試合についてもCLIの再演算と最終統計照合が成功。

### Raspberry Pi 5での実機確認

Raspberry Pi 5 Model B / 8GB / Debian 13 trixie / aarch64 / Cortex-A76 / Node 24.12で確認。既存アプリ用のシステムNode 22は変更せず、テトリス専用のNode 24を別に配置した。

- PCのブラウザからSSH転送を通してPi上の実サーバーへ接続し、2ブラウザ対戦/復帰/再戦、10人表示、RTT 30/100/200ms・揺らぎ・snapshot欠落を含むE2E 6件が成功。
- MyDNSのIPv4通知が成功し、`tetris.server-on.net` のAレコード解決を確認。
- 既存の2サイトを保持してテトリスを追加したCaddy設定候補を作成し、Pi上のCaddy 2.6.2でvalidate成功。公開設定への反映はまだ行っていない。
